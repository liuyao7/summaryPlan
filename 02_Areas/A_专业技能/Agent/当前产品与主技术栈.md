当前代表性 AI Agent 产品调研
一、编程领域 Agent（最成熟的领域）
1. Claude Code (Anthropic)
做到了什么：SWE-bench 评分 80.8%（所有商业工具中最高）。直接在终端（CLI）中运行，能读取和写入文件、运行测试、执行 git 提交。深度理解整个代码库，通过自然语言管理复杂 Git 工作流。
技术栈：基于 Claude 3.5/4 系列模型，支持 100万 Token 上下文窗口。集成 MCP（Model Context Protocol）连接数据库、API 和外部服务。CLI Agent 架构，拥有更深层的系统访问权限。
2. Cursor (Anysphere)
做到了什么：年度经常性收入 20亿美元，Tab 自动补全准确率超过 90%。多文件编辑、后台 Agent 自主完成任务、无缝模型切换（Claude/GPT/Gemini）。年收入证明其在开发者工作流中嵌入极深。
技术栈：由 Supermaven 驱动的自动补全引擎（速度行业领先），多模型路由架构。支持 Agent 模式下的后台自主任务执行。交互设计极强——Tab 键触发 + 对话框重构的模式使其维持了开发者的"心流体验"。
3. Devin (Cognition AI)
做到了什么：首个面向软件工程全流程的自主 Agent。设计了一个包含四个子界面的窗口：浏览器、IDE、用户交互区和测试环境。能完成完整软件工程闭环，包括代码编写、测试、Bug 修复、部署。
技术栈：独立的虚拟机环境（去掉 IDE，自己构建开发环境）。内置笔记系统（策略室/作战室），让 Agent 记录想法、修改系统设计架构、在思考环境中迭代。上下文引擎（Context Engine）实现对代码空间的深度理解。
4. Windsurf 2.0 (Cognition 收购前为 Codeium)
做到了什么：将本地 Cascade 代理与云端 Devin 代理融合。能执行命令、操作文件、检索网络技术文档作为参考。支持 70+ 种编程语言，推理延迟优化至业界领先水平。
技术栈：Deep Context 感知能力，FedRAMP 合规、本地部署、对 40+ IDE 的插件支持。OpenAI 于 2025年5月以 30亿美元 收购。
5. 文心快码 Comate (百度)
做到了什么：IDC 评估中"Agent能力"与"工程化落地"双满分。喜马拉雅实测代码采纳率 44%。C++ 生成质量行业第一。在吉利、顺丰等头部企业大规模私有化落地。
技术栈：SPEC 规范驱动（Spec-Driven）的多智能体架构，支持 SaaS + 私有化部署。
二、通用 Agent 产品
6. Manus (Monica)
做到了什么：号称"中国第一个通用 AI Agent"，获得 Benchmark 领投的 7500万美元 融资。内置 29个工具，能完成写作、信息收集、数据分析、代码编写和网页浏览等任务。最大成功在产品体验：让用户清晰看到 AI 完成任务的每一步，实时了解进展。
技术栈：多 Agent 协同工作（计划制定、总结、审查等功能模块），每个功能都需要多次调用大语言模型。使用 SFT（监督微调）技术对外围执行模块进行训练（非核心思维链）。依赖 Claude 3.7 Sonnet 等主流大模型。存在成本高、性能不稳定等问题，采用邀请码机制控制成本。
7. ChatGPT Agent / Operator (OpenAI)
做到了什么：Operator（2025年1月推出）具备自主使用浏览器能力。Deep Research（2025年2月推出）专注于复杂任务处理。搭载 GPT-5.4 后能力大幅提升，集成文本生成、图像创建、语音对话、实时网页浏览、代码执行。
技术栈：基于 GPT-5.4 大模型，端到端 RL（强化学习）训练的自主规划能力。Computer Use Agent 技术（模拟人类操作浏览器）。
三、企业自动化平台
8. 扣子空间 Coze (字节跳动)
做到了什么：一站式智能体构建平台，支持企业自定义工作流。低代码/零代码方式快速创建并部署到飞书、抖音等字节生态。
技术栈：工作流编排引擎，多 Agent 协同，插件生态。字节生态深度整合。
9. AutoGLM / Kimi 智能体 (智谱AI / 月之暗面)
做到了什么：AutoGLM 是 GUI 型 Agent，能直接接管手机屏幕，模拟人类点击和输入。Kimi-Researcher 专注研究领域。Kimi 凭借 AgentSwarm 集群技术在复杂任务处理上表现突出。
技术栈：原生多模态架构 + AgentSwarm 集群技术，长上下文理解，多轮任务规划。
10. CrewAI
做到了什么：多 Agent 角色分工协作框架。允许定义不同角色的 Agent（研究员、评审员、写手等）协同完成任务。内容创作、市场分析等场景表现好。
技术栈：开源 Python 框架（GitHub 30k+ stars），基于 LangChain，支持 OpenAI/Anthropic/Google/Azure 等多种大模型提供商。
四、三个核心趋势总结
根据 MIT、哈佛、斯坦福等机构联合发布的《AI Agent Index》报告，当前 Agent 产品形态收拢在三个方向：

类型	代表产品	数量占比	核心技术特点
聊天式 Agent	ChatGPT Agent, Claude, Manus	12/30	对话入口 + 工具箱挂载
企业自动化平台	Coze, Dify, 钉钉AI	13/30	B端工作流自动化编排
浏览器/GUI型 Agent	Operator, AutoGLM, Fellou	5/30	接管屏幕，模拟人类点击输入
三个重要发现：

多 Agent 协作成为主流：不再是单个 Agent 单打独斗，而是"规划 Agent + 执行 Agent + 审查 Agent"协同作战，架构正成为标配。
MCP 协议统一了工具调用标准：Agent 通过统一协议连接外部 API、数据库和文档，不再需要为每个工具编写特定插件。
A2A + MCP + Skills 构成 2026 年 AI 应用基础设施：A2A 让 Agent 间协作，MCP 让 Agent 连接外部世界，Skills 让 Agent 掌握特定领域知识。
四、开源 Agent 框架（OpenClaw / Hermes Agent）

11. OpenClaw
定位：生产级多渠道 Agent 平台，TypeScript 项目（43万行代码），MIT 开源。
做到了什么：
- 1个编排者 + 5个专业Agent + 6个ACP编码专家、52个Cron定时任务每天自动轮转、118个Skills、29个LLM模型
- Agent 不需要等用户发消息，自己就是"上班族"——Cron定时主动叫醒Agent干活
- 从凌晨3点的自动备份到23:45的团队反思，实现 Agent 自我进化：犯过的错从 .learnings/ promote 到 MEMORY.md，同类问题复发率显著下降
- 完整链路：哨兵Agent发现开源项目/论文 → 评估影响 → 进入 Tech Radar → 委派编码Agent落地
技术栈（五层架构）：
- Gateway：WebSocket服务，统一收发消息
- Channel：23+渠道适配器（Telegram/飞书/Discord/微信等），消息扔进 MessageBus"信箱"，与Agent核心完全解耦
- Pi Agent：ReAct主循环，会话状态调度，子Agent生成（Spawn）
- 工具集：Shell、文件、浏览器控制，按ACI原则设计
- 上下文+记忆：Skills延迟加载、MEMORY.md、Token超标自动压缩
容错机制（五层）：错误分类 → 智能重试 → API Key级别故障转移 → 模型/提供商级别故障转移 → 上下文溢出自动压缩
模型回退链：gpt-5.4 → k2.5 → qwen3.5-plus → ollama/qwen3:8b
与LangChain/AutoGPT的区别：Gateway常驻（非请求-响应）、26+内建渠道、Skill按需加载、多层容错、Cron定时任务
核心设计思想：事件驱动——每个关键节点发射事件，日志/UI/评测/审核各自监听，Agent核心代码极干净。

12. Hermes Agent
定位：自进化 AI Agent（"与你共同成长的Agent"），Nous Research 开发，Python 93.6% + SQLite，MIT 开源，GitHub 110K+ Stars，2026年2月发布后长期霸榜 Trending 第一。
做到了什么：
- 唯一具有闭环自学习系统的开源 Agent 框架
- 使用自创技能的 Agent 完成任务比全新实例快 40%（无需 Prompt Tuning）
- 技能库可从 40个增长到 200个，但上下文成本几乎不变
技术栈（闭环学习五步循环）：
- 接收 → 检索（FTS5全文搜索）→ 推理与行动（LLM+工具）→ 记录（自动生成Skill文档）→ 持久化（存入记忆供未来检索）
四层记忆系统（核心竞争力）：
- 第一层（常驻提示）：MEMORY.md + USER.md，字符上限拉紧到3575个，故意收窄强迫筛选
- 第二层（会话归档）：SQLite + FTS5全文索引，Agent按需查询历史，结果经LLM摘要后注入
- 第三层（技能文件）：学习循环产物，遵循 agentskills.io 开放标准，40→200个，上下文成本几乎不变
- 第四层（Honcho）：可选用户建模层，跨会话积累偏好、沟通风格、领域知识
MemPalace（记忆宫殿，灵感来自古希腊记忆术）：Wing(项目) → Hall(记忆类型) → Room(话题) → Closet(压缩摘要) → Tunnel(跨话题引用)
仅靠此层级结构，检索准确率 60.9% → 94.8%。
核心判断：不应该让AI来决定什么值得记——AI判断不可信，不如全存下来，让检索来决定什么有用。
多模型编排（Auxiliary Models）——主对话用昂贵模型，图像分析/网页提取/Skill匹配/记忆处理等侧任务自动切到轻量模型（默认Gemini Flash）
200+模型后端：OpenAI、Anthropic、Bedrock、OpenRouter、DeepSeek、Hugging Face、Ollama、阿里DashScope、小米MiMo等
执行后端：local / Docker / SSH / Daytona / Singularity / Modal（支持无服务器持久化）
渠道：8个平台（Telegram/Discord/Slack/飞书等）
内置Tinker-Atropos RL环境，可用于训练数据生成和模型微调。

OpenClaw vs Hermes Agent 核心对比：
维度	OpenClaw	Hermes Agent
主语言	TypeScript 90%+	Python 93.6%
核心定位	多渠道 Multi-Agent 编排平台	单一 Agent 自进化框架
进化方式	配置文件 + Multi-Agent 协作	闭环自学习循环（自动创建/改进Skill）
渠道覆盖	50+ 平台（含原生 App）	~8 个平台
记忆系统	MEMORY.md + 上下文压缩	四层记忆 + FTS5全文搜索 + MemPalace
适用场景	复杂编排的企业级自动化	长期记忆、个性化、持续成长的个人助手
学习价值	教你做"工程编排"	教你做"记忆与自进化架构"

选型建议：
- 需要自进化、长期记忆、越用越聪明 → Hermes Agent
- 需要多渠道覆盖(50+)、多Agent编排、定时任务自动化 → OpenClaw
- Agent研究和训练数据生成 → Hermes Agent（Tinker-Atropos RL + 轨迹压缩）
- Python栈开发者想研究闭环学习 → Hermes Agent
- TypeScript/Node栈开发者想做生产级平台 → OpenClaw

五、对 Agent 工程师的技术启示
从这些产品中，可以提炼出 Agent 工程师需要掌握的三大核心技术三角：

ReAct 范式（感知-推理-行动闭环）：所有优秀 Agent 都遵循"思考 → 行动 → 观察 → 再思考"的循环。
环境构建能力：Devin 的虚拟机环境、Cursor 的 IDE 上下文引擎、Manus 的工具集——环境定义决定了 Agent 的能力边界。环境比数据更重要。
评估（Evaluation）比训练（Training）更重要：Harness Engineering 正在成为核心竞争力——与其期待更强的模型，不如专注于最大化利用当前模型的能力。
