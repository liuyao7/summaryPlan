# ReAct 范式（Reason + Act）

## 一、为什么需要 ReAct？

ChatGPT 的训练数据有截止时间，它不知道今天的天气。直接问"今天天气怎么样"，它只能编一个答案——这就是**幻觉**。

Agent 要解决的问题是：让大模型不只是一个"嘴"，还要长"手"（调用工具），还要有"脑子的回路"（循环推理）。

> 模型再强也只是"高级顾问"——它能给出完美的答案，却无法帮你把事情完成。

ReAct 的使命：**让大模型从"回答问题"升级为"执行任务"。**

---

## 二、ReAct 的四步心跳循环

ReAct = **Re**ason（推理） + **Act**（行动）

```
用户提问
  ↓
┌─────────────────────────────────┐
│ ① 思考(Reason)：我现在该干什么？    │
│ ② 行动(Act)：调用工具/执行操作      │
│ ③ 观察(Observe)：工具返回了什么？   │
│ ④ 判断：完事了没？没完→回到①       │
└─────────────────────────────────┘
  ↓
最终回复用户
```

### 实例：查天气 + 给建议

```
用户：今天北京天气怎么样？下雨带伞，晴天爬山

第1轮
  思考：用户想知道天气，我需要调天气工具
  行动：调用 get_weather("北京")
  观察：{ "天气": "小雨", "温度": "18°C" }
  判断：还没完，我得根据天气给建议

第2轮
  思考：天气是小雨，用户说下雨提醒带伞
  行动：不需要调工具了，直接回复
  观察：无
  判断：任务完成 ✓
```

**核心认知**：Agent 不是一次性回答，而是在多轮循环中逐步推进任务。每一步都停下来看看上一步的结果，再决定下一步往哪走。

## 三、人类类比

把 Agent 想象成一个有电话、计算器、记事本的客服：

```
用户：帮我算一下，5000块钱转给张三，交完200水电费，还剩多少？张三账号正常吗？

第1步 思考：先查张三账号状态
       行动：打电话给账户部
       观察："正常"
第2步 思考：账号正常，现在算余额
       行动：用计算器 5000 - 200
       观察：4800
第3步 思考：两件事都做完了
       直接回复用户
```

**ReAct Agent 就是在模拟人的工作方式**：大脑决定做什么，手脚执行，观察结果喂回大脑继续思考。

## 四、核心循环伪代码

```javascript
async function agentLoop(userQuestion) {
  // messages 是 Agent 的"工作记忆"
  const messages = [
    { role: "system", content: "你是助手，可以使用工具。" },
    { role: "user", content: userQuestion }
  ];

  for (let i = 0; i < 10; i++) {
    // ① 思考：让大模型决定下一步
    const response = await callLLM(messages);

    // 直接回复文本 → 任务完成
    if (response.type === "text") {
      return response.content;
    }

    // ② 行动：模型要调用工具
    if (response.type === "tool_call") {
      const toolName = response.toolName;
      const toolArgs = response.toolArgs;

      // ③ 观察：执行工具，拿到结果
      const toolResult = await executeTool(toolName, toolArgs);

      // 把"我要干什么"和"干完得到了什么"都写进记忆
      messages.push({ role: "assistant", toolCall: response });
      messages.push({ role: "tool", result: toolResult });

      // ④ 循环回去，让模型看看结果再决定
      continue;
    }
  }

  return "任务超时";
}
```

**整个逻辑不到 30 行，这就是 Agent 的心脏。**

## 五、messages（对话记录）的演变——理解 ReAct 的关键

### 第1轮开始时
```
messages = [
  { role: "system", content: "可用工具: get_weather(city)" },
  { role: "user", content: "今天北京天气怎么样？下雨带伞晴天爬山" }
]
```

### 第1轮 LLM 返回
`{ type: "tool_call", toolName: "get_weather", toolArgs: { city: "北京" } }`

### 第1轮结束后（追加两条记录）
```
messages = [
  { role: "system", ... },
  { role: "user", ... },
  { role: "assistant", toolCall: get_weather("北京") },         // 我决定干什么
  { role: "tool", result: { "天气": "小雨", "温度": "18°C" } } // 干了之后得到什么
]
```

### 第2轮
LLM 看到的 messages 已经包含了上一轮的行动和观察，它知道天气是小雨 → 直接返回文本：

_"今天北京小雨，18°C，记得带伞哦！"_

**这就是 ReAct 的全部秘密**：把每一轮的行动和观察都写进对话记录，像人记笔记一样——边做边记，根据笔记决定下一步。

## 六、为什么必须循环而不能一步到位？

模型在决定"第二步"之前，**必须先知道**第一步工具执行的结果。如果不知道结果就往下规划——那是猜，猜就会出错。

```
能做事（ReAct 循环）：
  思考 → 行动 → 拿到结果 → 基于结果再思考 → ...

会做错（一步到位）：
  思考：先查天气，如果是雨就提醒带伞，如果是晴就建议爬山
  行动：直接建议爬山（但实际下雨） ❌ 幻觉
```

## 七、ReAct 循环为什么极度稳定？

从 LangChain 到 OpenClaw 到 Hermes，所有 Agent 框架的核心循环几乎一模一样：

```
所有 Agent 框架 = ReAct 循环 + 工具集 + 记忆系统 + 运维能力
```

新增的能力全部挂在循环**外部**，循环体本身不需要变：

| 想加的能力 | 加在哪里 | 需要改循环？ |
|-----------|---------|:--:|
| 加一个新工具 | 工具注册表 | 否 |
| 长期记忆 | messages 外加向量检索 | 否 |
| 追踪 Token 消耗 | callLLM 外包一层 | 否 |
| 人工审核（危险操作暂停） | executeTool 前拦截 | 否 |
| 子 Agent 委派 | 子Agent注册为"工具" | 否 |

> 设计之美：核心极简，能力外挂。模型负责推理，外部系统负责状态和边界。

---

## 八、三个核心认知

1.**ReAct 是一个循环**，不是一次性调用。模型每轮根据当前掌握的信息决定下一步。

2.**messages 是 Agent 的工作记忆**。每次行动和观察都追加进去，让下一轮看到完整历史。

3.**这个循环是所有 Agent 系统的地基**。万变不离其宗，所有框架都在这个循环上叠能力。
