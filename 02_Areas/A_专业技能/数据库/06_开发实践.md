## 6.1 ORM 框架

### 必须掌握

#### MyBatis / MyBatis-Plus（Java 生态）

| 知识点 | 说明 |
|--------|------|
| `#{}` vs `${}` | `#{}` 是预编译占位符（防注入），`${}` 是字符串拼接（有注入风险） |
| ResultMap | 处理列名 → 属性名的映射，复杂对象嵌套映射（association / collection） |
| 动态 SQL | `<if>` `<choose>` `<foreach>` `<where>` `<set>` — 灵活但有维护成本 |
| 插件机制 | 分页插件（PageHelper）、拦截器（SQL 审计、慢查询监控） |
| 缓存 | 一级缓存（SqlSession 级别，默认开启）、二级缓存（Mapper 级别，需谨慎） |
| MyBatis-Plus | Lambda 查询（类型安全）、自动分页、代码生成器、逻辑删除 |

#### JPA / Hibernate

| 知识点 | 说明 |
|--------|------|
| 实体映射 | `@Entity` `@Table` `@Id` `@GeneratedValue` `@Column` `@Enumerated` |
| 关系映射 | `@OneToOne` `@OneToMany` `@ManyToOne` `@ManyToMany` + FetchType（LAZY / EAGER） |
| JPQL / Criteria API | 面向对象的查询语言 |
| 生命周期 | Transient → Managed → Detached → Removed |
| 注意事项 | N+1 查询陷阱（`@OneToMany(fetch = LAZY)` + 循环调用 getter） |

#### 通用设计原则

- ORM ≠ 不需要懂 SQL。复杂查询必须手写 SQL 并 review 执行计划
- 禁止循环中逐条插入/更新，必须用批量操作
- DAO 层单一职责：只做数据存取，不含业务逻辑

## 6.2 连接池管理

### 必须掌握

#### HikariCP（Spring Boot 默认，业界最快）

| 配置项 | 含义 | 推荐值 |
|--------|------|--------|
| `maximumPoolSize` | 最大连接数 | CPU 核数 * 2 + 磁盘数（通常 10~20） |
| `minimumIdle` | 最小空闲连接 | 与 maximumPoolSize 相同（避免频繁创建/销毁） |
| `connectionTimeout` | 等待连接超时 | 30000ms（30 秒），超长则上游已超时 |
| `idleTimeout` | 空闲连接超时 | 600000ms（10 分钟） |
| `maxLifetime` | 连接最大存活时间 | 比数据库 wait_timeout 短 2~3 分钟 |

#### Druid（阿里开源，监控能力强）

- 内置 SQL 监控 + 防火墙（防注入）+ 连接泄漏检测
- 可视化管理页面（/druid/index.html）

#### 连接数如何计算

```
最大连接数 = ((CPU 核数 * 2) + 磁盘数) / 每个查询平均耗时(ms) * 1000 / 期望 QPS
简化公式： 通常 10~20 连接足够单个微服务实例
```

#### 连接泄漏

- **现象**：连接数持续上涨 → 耗尽 → `HikariPool - Connection is not available`
- **排查**：Druid 的 `removeAbandoned=true`、`SHOW PROCESSLIST` 找长时间 Sleep 连接
- **预防**：确保每个连接在 finally 中关闭；Try-with-resources

>    - 设置为 20 → 同样的并发 → 对比

> 5. 通过 Druid 监控页面复现并定位连接泄漏的堆栈

## 6.3 Schema 版本管理

### 必须掌握

#### Flyway

```
V1__init.sql      → 初始表结构
V2__add_age.sql   → 加 age 列
V3__create_index.sql → 加索引
R__refresh_view.sql  → 可重复执行（视图/存储过程）
```

- **命名规范**：`V{版本号}__{描述}.sql`（双下划线）
- **版本管理**：用 `flyway_schema_history` 表记录已执行的迁移
- **修复状态**：`flyway repair` 修复 checksum 不一致

#### 最佳实践
- 每个 DDL 或 ID 不敏感的 DML 独立为一个版本文件
- 每次迁移必须可回滚（写对应的 undo SQL）
- 禁止手动改数据库表结构，一切通过 Flyway/Liquibase
- CI/CD 中集成：部署前自动执行 pending migrations

### 学后任务

> Flyway 实战：
> 1. 在 Spring Boot 项目中集成 Flyway
> 2. 编写 3 个版本迁移脚本：
>    - V1：创建 user 表（id, username, password_hash, created_at）
>    - V2：给 user 表加 phone 列
>    - V3：创建 order 表（id, user_id, amount, FOREIGN KEY）
> 3. 故意修改已执行过的 V2 文件 → 启动报错 → `flyway repair` 修复
> 4. 验证：用 Git 管理 SQL 文件，切到历史版本 + 运行 migration 能否复现历史表结构

## 6.4 批量操作与性能

### 必须掌握

| 操作 | 反模式 | 正解 |
|------|--------|------|
| 批量插入 | for 循环 INSERT | JDBC batch INSERT / INSERT INTO ... VALUES (...), (...), (...) |
| 批量更新 | for 循环 UPDATE | CASE WHEN 批量更新 / 临时表 + JOIN UPDATE |
| 大量数据导出 | SELECT * 一次全拉 | 游标/分页流式读取 |
| 关联查询 | 查完 A 再循环查 B（N+1） | JOIN / IN (...) 批量查询 |

#### 各框架批量插入方式

```sql
-- 原生 SQL：一次性插入多条（不宜太大，建议每批 500~1000 条）
INSERT INTO users (name, age) VALUES ('a', 1), ('b', 2), ('c', 3);
```

```java
// MyBatis: foreach 标签
<insert id="batchInsert">
    INSERT INTO users (name, age) VALUES
    <foreach collection="list" item="item" separator=",">
        (#{item.name}, #{item.age})
    </foreach>
</insert>

// MyBatis-Plus: saveBatch()
userService.saveBatch(userList, 500);
```

## 6.5 常见开发反模式

### 必须掌握

| 反模式 | 说明 | 后果 | 正解 |
|--------|------|------|------|
| **N+1 查询** | 查 N 条主记录后再逐条查关联 | 性能灾难 | JOIN / IN 批量 |
| **SELECT *** | 查出所有列 | IO 浪费、覆盖索引失效 | 只 SELECT 需要的列 |
| **隐式类型转换** | WHERE varchar_col = 123 | 索引失效 + 全表扫描 | 保持类型一致 |
| **函数包裹列** | WHERE DATE(created_at) = '2026-05-01' | 索引失效 | WHERE created_at >= '...' AND created_at < '...' |
| **大事务** | 一个事务更新大量行 | 锁等待、主从延迟 | 分批提交 |
| **MySQL 中存储大文件** | 存图片/视频到 BLOB | 表膨胀、备份慢 | 存 OSS/COS，数据库存 URL |
| **WHERE 中 OR 条件** | WHERE a=1 OR b=2（a,b 各自有索引） | 可能全表扫描 | UNION 替代 |
| **COUNT(*) vs COUNT(col)** | COUNT(col) 不统计 NULL | 结果偏差 | COUNT(*) 统计行数 |
