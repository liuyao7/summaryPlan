## 7.1 备份与恢复

### 必须掌握

#### 备份类型

| 类型 | 工具 | 特点 |
|------|------|------|
| 逻辑备份 | mysqldump / pg_dump | SQL 文本，跨版本兼容，大数据量慢 |
| 物理备份 | XtraBackup / pg_basebackup | 文件级拷贝，速度快，但依赖版本/平台 |
| 全量备份 | — | 完整数据快照 |
| 增量备份 | binlog 持续备份 | 减少备份量，依赖全量备份做基础 |
| 差异备份 | — | 上次全量以来的变化，恢复比增量快 |

#### 最佳实践

- **备份策略**：每天全量 + 每小时增量 binlog → 任意时间点恢复（PITR）
- **备份验证**：定期在测试环境恢复备份，确保可用
- **异地容灾**：备份文件同步到异地/其他云厂商
- **保留周期**：全量 30 天、增量 7 天（按业务 RPO 定）

#### mysqldump 常用参数

```bash
# 单库备份
mysqldump -u root -p --single-transaction --routines --triggers mydb > backup.sql

# 全库备份
mysqldump -u root -p --all-databases --single-transaction > all.sql

# 只备份表结构
mysqldump -u root -p --no-data mydb > schema.sql
```

- `--single-transaction`：InnoDB 一致性备份（不锁表）
- `--master-data=2`：记录 binlog 位置（用于 PITR）

## 7.2 监控指标与告警

### 必须掌握

#### 核心指标

| 指标 | 含义 | 告警阈值建议 |
|------|------|-------------|
| **QPS（每秒查询数）** | `Questions / Uptime` | 超过历史峰值 2 倍 |
| **TPS（每秒事务数）** | `Com_commit + Com_rollback` | 同上 |
| **连接数** | `Threads_connected` | 超过 max_connections 的 80% |
| **活跃连接** | `Threads_running` | > CPU 核数 × 2 |
| **锁等待** | `Innodb_row_lock_waits` 增长 | 持续增长需排查 |
| **慢查询** | Slow_queries 增量 | 超过 5 条/分钟 |
| **复制延迟** | `Seconds_Behind_Master` | > 5 秒 |
| **缓冲池命中率** | `Innodb_buffer_pool_read_requests / (reads + read_requests)` | < 95% |
| **磁盘使用率** | 数据目录 + binlog 目录 | > 80% |

#### 常用监控工具

| 工具 | 用途 |
|------|------|
| **Prometheus + mysqld_exporter** | 指标采集 + 图表 + 告警 |
| **Grafana** | 可视化仪表盘（社区有 MySQL 模板） |
| **pt-query-digest** | 慢查询日志聚合分析 |
| **PMM（Percona Monitoring）** | 一键 MySQL 监控（企业级） |
| **阿里云 DAS / 腾讯云 DBbrain** | 云厂商自带智能诊断 |

>    - 慢查询数量趋势
>    - 复制延迟（如有主从）
> 4. 用 sysbench 压测 MySQL，观察 Grafana 面板波动
> 5. 配置 Prometheus Alert Rules：
>    - 连接数 > 80% → 告警

## 7.3 安全实践

### 必须掌握

#### SQL 注入防御

```java
// ❌ 危险：拼接 SQL
String sql = "SELECT * FROM users WHERE name = '" + userName + "'";

// ✅ 安全：预编译
String sql = "SELECT * FROM users WHERE name = ?";
PreparedStatement ps = conn.prepareStatement(sql);
ps.setString(1, userName);
```

| 防御手段 | 说明 |
|----------|------|
| **预编译（PreparedStatement / #{} ）** | 参数与 SQL 分离，**第一道防线** |
| **输入校验** | 长度、类型、格式白名单校验 |
| **最小权限原则** | 应用账号只有 CRUD 权限，不能 DDL |
| **禁用危险函数** | 数据库端禁用 xp_cmdshell, LOAD_FILE 等 |
| **WAF** | Web 应用防火墙拦截注入请求 |
| **错误信息脱敏** | 不暴露数据库类型、表名、堆栈 |

#### 权限管理

```sql
-- 创建应用专用账号（而非直接用 root）
CREATE USER 'app_user'@'%' IDENTIFIED BY 'strong_password';

-- 最小权限
GRANT SELECT, INSERT, UPDATE, DELETE ON mydb.* TO 'app_user'@'%';

-- 禁止 GRANT 传递
REVOKE GRANT OPTION ON mydb.* FROM 'app_user'@'%';
```

#### 数据加密

| 场景 | 方案 |
|------|------|
| 传输加密 | TLS/SSL 连接（`require_secure_transport=ON`） |
| 存储加密 | InnoDB 表空间加密（`encryption='Y'`） |
| 敏感字段 | 应用层加密（AES）+ 密钥管理（KMS） |

## 7.4 容量规划与归档

### 必须掌握

#### 数据增长预估

```
当前总数据量 / 运行天数 = 日均增量
日均增量 × 365 = 年增量
年增量 × N = N 年后的总量
```

#### 归档策略

| 策略 | 说明 | 适用 |
|------|------|------|
| 按时间分区 | 原生 Partition，快速删除过期分区 | 日志/流水 |
| 冷热分离 | 热数据（近 3 月）在 SSD，冷数据在 HDD/OSS | 订单/操作记录 |
| 归档表 | 定期移动历史数据到 archive 表 | 通用 |
| TTL（Time-To-Live） | 超期数据自动删除 | IoT 传感器数据 |

#### MySQL 分区

```sql
-- 按范围分区（每月一个分区）
CREATE TABLE orders (
    id BIGINT,
    created_at DATETIME NOT NULL
) PARTITION BY RANGE (YEAR(created_at) * 100 + MONTH(created_at)) (
    PARTITION p202601 VALUES LESS THAN (202602),
    PARTITION p202602 VALUES LESS THAN (202603),
    ...
);
-- 删除过期分区：ALTER TABLE orders DROP PARTITION p202601;
```
