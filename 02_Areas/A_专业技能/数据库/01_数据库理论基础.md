## 1.1 关系模型与关系代数

### 必须掌握

- **表（Relation）**：行 = 元组（Tuple），列 = 属性（Attribute），每列有确定的数据类型（域 Domain）
- **主键（Primary Key）**：唯一标识一行，不可为空；业务主键 vs 代理主键（自增ID/UUID）
- **外键（Foreign Key）**：表间引用约束，保证参照完整性；ON DELETE/UPDATE 的 CASCADE / SET NULL / RESTRICT 行为
- **唯一约束（Unique）**、**检查约束（Check）**、**非空约束（Not Null）**、**默认值（Default）**
- **关系代数**：选择 σ、投影 π、并 ∪、差 −、笛卡尔积 ×、重命名 ρ。重点理解 JOIN 的本质是笛卡尔积 + 选择

## 1.2 数据库范式（Normalization）

### 必须掌握

| 范式 | 核心规则 |
|------|---------|
| **1NF** | 列不可再分（禁止嵌套表/数组列） |
| **2NF** | 非主属性完全依赖于**整个**主键（消除部分依赖，针对联合主键） |
| **3NF** | 非主属性不传递依赖于主键（消除传递依赖，即非主属性不能依赖另一个非主属性） |
| **BCNF** | 所有决定因素都是候选键（比 3NF 更严格，处理主属性间的依赖） |

- **能举例**：订单表（订单ID, 商品ID, 商品名, 单价）违反 2NF → 拆成订单表 + 商品表
- **能举例**：学生表（学号, 姓名, 系名, 系主任）违反 3NF → 拆成学生表 + 系表

## 1.3 ACID 特性

### 必须掌握

| 特性 | 含义 | 实现方式 |
|------|------|----------|
| **原子性（Atomicity）** | 事务要么全部成功，要么全部回滚 | Undo Log（回滚日志） |
| **一致性（Consistency）** | 事务前后数据满足所有约束 | 约束检查 + 原子性/隔离性共同保证 |
| **隔离性（Isolation）** | 并发事务互不干扰 | 锁 + MVCC（详见第03模块） |
| **持久性（Durability）** | 提交的事务不会丢失 | Redo Log（重做日志） + WAL |

- 理解 WAL（Write-Ahead Log）机制：修改数据前先写日志，崩溃后通过日志恢复
- 理解 Checkpoint 的作用：减少恢复时需要重放的日志量

## 1.4 CAP 定理

### 必须掌握

- **C（Consistency）**：所有节点同一时刻数据一致（强一致性）
- **A（Availability）**：每个请求都能获得非错误的响应（不一定是最新数据）
- **P（Partition Tolerance）**：系统在任意网络分区故障时仍能正常运行
- 核心结论：分布式系统中 P 必须保证，只能在 C 和 A 之间取舍

| 取舍 | 代表数据库 | 场景 |
|------|-----------|------|
| CP（强一致） | ZooKeeper、HBase | 金融、配置管理 |
| AP（高可用） | Cassandra、DynamoDB | 社交、IoT |
| CA（无分区） | 传统单机 RDBMS | 单机场景 |

## 1.5 存储引擎

### 必须掌握

- **B+Tree**（MySQL InnoDB 默认）：
  - 所有数据在叶子节点，叶子节点形成有序链表
  - 叶子节点存完整行数据（聚簇索引），非叶子节点只存键 + 指针
  - 适合：点查、范围查询、排序。每个节点 ~16KB（一页）
- **LSM-Tree**（RocksDB、LevelDB、HBase）：
  - 写入先到 MemTable（内存），满了刷成 SSTable（磁盘），后台合并（Compaction）
  - 适合：写多读少、时序数据。写放大是主要问题
- **Hash 索引**：O(1) 精确查询，但无序 → 不支持范围查询和排序
