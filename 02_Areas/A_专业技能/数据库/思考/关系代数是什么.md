# 关系代数是什么

## 背景

体育专业出身、做过一段前端工程师，现在转向学习后端和数据库。学习 SQL 时发现它和"关系代数"有关，想搞清楚关系代数到底是什么。

## 一句话解释

关系代数是一套**"对表做运算"的数学规则**，SQL 就是它的工程化语言外壳。

## 类比理解（从熟悉的东西出发）

- 小学算术：操作数是**数字**，运算符是 `+ - × ÷`
- 关系代数：操作数是**表（关系）**，运算符是**选择、投影、连接**等
- 共同点：输入和输出**类型一致**。算术里数 + 数 = 数；关系代数里表 op 表 = 表 → 所以可以**层层嵌套**，这正是 SQL 子查询能成立的根基。

体育类比：把"表"想成一份**球员名单 Excel**，关系代数就是"筛选行 / 挑选列 / 把两份名单拼起来"的标准动作。

## 6 个核心运算（够用了）

假设有两张表：

- `Players(id, name, team_id, age)`
- `Teams(team_id, team_name, city)`

| 关系代数 | 通俗说法 | 对应 SQL |
|---|---|---|
| σ (Selection) 选择 | 按条件**筛行** | `WHERE age > 25` |
| π (Projection) 投影 | 只**取某几列** | `SELECT name, age` |
| × (Cartesian) 笛卡尔积 | 两表**所有行两两组合** | `FROM A, B` |
| ⋈ (Join) 连接 | 笛卡尔积 + 条件筛选 | `JOIN ... ON ...` |
| ∪ / − (Union/Diff) | 两表行**合并 / 相减** | `UNION` / `EXCEPT` |
| ρ (Rename) 重命名 | 改列名 / 表名 | `AS` |

## 一个完整例子

需求：找出"湖人队"所有球员的名字。

**关系代数写法**：

```
π_name ( σ_team_name='Lakers' ( Players ⋈ Teams ) )
```

**翻译过来**：

1. `Players ⋈ Teams`：把两张表按 team_id 连起来
2. `σ_team_name='Lakers'`：从中筛出球队名是 Lakers 的行
3. `π_name`：只保留 name 这一列

**对应 SQL**：

```sql
SELECT name
FROM Players JOIN Teams ON Players.team_id = Teams.team_id
WHERE team_name = 'Lakers';
```

可以看到，SQL 几乎是关系代数的"自然语言版翻译"。

## 为什么要学它（对当前阶段最重要的部分）

1. **看懂 SQL 执行计划**：数据库引擎拿到 SQL 后，内部就是先翻译成关系代数表达式，然后做**等价变换**来优化（比如把 σ 下推到 ⋈ 之前，先筛后连，数据量更小）。这就是"查询优化器"的本质。
2. **写出可优化的 SQL**：理解了等价变换规则，就知道为什么"先 WHERE 再 JOIN"和"先 JOIN 再 WHERE"在某些情况下结果一样但性能差很多。
3. **从前端思维切换到后端思维**：前端处理的多是树状 / 对象数据；关系代数训练用**集合的方式思考**——这是数据库、数据分析的通用心智模型。

## 学习建议

- 先记住上面 6 个运算符，能在纸上把简单 SQL 翻译成关系代数表达式即可
- 不用啃形式化定义，重点是**直觉**：每个运算输入是表、输出也是表
- 进阶再看：等价变换规则 → 查询优化 → 索引为什么能加速 σ 和 ⋈
