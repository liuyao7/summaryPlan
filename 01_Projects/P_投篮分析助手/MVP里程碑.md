# 投篮分析助手 - MVP 里程碑

> 版本：v2.0（基于公开调研重写）
> 创建日期：2026-06-01
> 团队：1 人 + Coding Agent

---

## 0. 修订说明

v2.0 相对 v1.0 的关键变化：
- 加入 **Stage 0 Spike 阶段**：未验证假设前不进 MVP
- 把 v1.0 的"6 周交付完整产品"改为 **三个独立 Stage**，每个 Stage 都可独立交付/止损
- 球星视频/比例匹配等高风险/伪需求功能**不进 MVP**
- 责任人/工时按 1 人独立开发实际估算
- 验收检查清单与公开标准对齐（Okazaki / Irawan / Bin Chi / Fontanella）

---

## 1. 总目标

> **MVP 不是"完整产品"，是"被 5 个真实业余球员上传过视频并觉得有用"**。

如果 Stage 0 的 Spike 都跑不通，本项目应**立即止损**或**重新选型**，而不是硬推进。

---

## 2. Stage 0 · 技术 Spike（1 周）

### 目标

证明 **「浏览器端能在合理时间内，对 30s 投篮视频做完整逐帧 BlazePose 检测，并对至少 1 条规则给出可解释的诊断」**。

### 任务

| # | 任务 | 状态 | 验收标准 |
|---|------|------|---------|
| 0.1 | Web 原型骨架（已完成） | ✅ | `prototype/` 可启动 |
| 0.2 | BlazePose 模型加载与推理 | ⬜ | 桌面 Chrome 加载 < 5s |
| 0.3 | 视频抽帧 + 逐帧检测 | ⬜ | 10s 视频 < 30s 完成；无丢帧 |
| 0.4 | Canvas 骨骼可视化 | ⬜ | 33 点 + 连线，肉眼检查无错位 |
| 0.5 | 规则 R1 (肘部外翻) 实现 | ⬜ | 上臂外展角峰值与人工估测误差 < 5° |
| 0.6 | 测试视频集（5 段） | ⬜ | 自录或邀请：3 段标准 + 2 段故意外翻 |
| 0.7 | 跨浏览器验证 | ⬜ | iOS Safari + Android Chrome 跑通 |
| 0.8 | Spike 验收报告 | ⬜ | 决定进 MVP 或回头重选 |

### 决策点

```
Spike 全部通过 → 进入 Stage 1
Spike 大部分通过 (≥ 6/8) → 评估降级方案后再决定
Spike 关键项不通过 (0.2/0.3/0.5) → 重新选型
```

### 交付物

- 可运行的 Web 原型
- 性能测试数据表（设备 × 视频长度 × 耗时）
- Spike 验收报告（写成 `prototype/SPIKE_REPORT.md`）

## 3. Stage 1 · MVP v1（3 周，Spike 通过后开始）

### 目标

让 5 个业余球员上传过自己的投篮视频，并至少 3 个反馈"看到了我以前没意识到的问题"。

### 里程碑

#### M1.1 · Week 1：核心管线打磨

| 任务 | 验收 |
|------|------|
| 项目结构升级（视情况引入 Vite + TS） | 构建产物可部署 |
| 上传页 + 拍摄引导（45°/侧面/正后方图示） | 至少展示 3 种角度的对错示例 |
| 投篮区间切分（基于手腕 y 拐点） | 在 20 段测试视频上 ≥ 70% 正确切分 |
| 规则 R1（肘外翻）正式实现 + 严重等级 | 阈值: <15/15-25/25-35/>35 度 |

#### M1.2 · Week 2：规则扩展

| 任务 | 验收 |
|------|------|
| 规则 R2（出手过低） | 腕高与头顶 y 比对 |
| 规则 R3（膝蓄力不足） | 蓄力相最小膝角检测 |
| 规则 R4（前臂未垂直） | 前臂与铅垂线夹角 |
| 规则 R5（无 follow-through） | 出手后 300ms 腕鞭打检测 |

#### M1.3 · Week 3：报告与上线

| 任务 | 验收 |
|------|------|
| 诊断报告页（自然语言 + 标注帧）| 5 条规则都有对应文案 |
| 移动端适配 | iPhone 13 / Android 中端机能用 |
| IndexedDB 历史记录 | 本地保存 ≥ 10 条 |
| Vercel 部署 | 公网可访问 |
| 5 名真实用户灰度测试 | 收集反馈 |

### 验收清单（功能）

- [ ] 视频上传成功（mp4/mov ≤ 50MB）
- [ ] 拍摄引导清晰（45°/侧面/正后方）
- [ ] 桌面 Chrome 30s 视频分析 < 90s
- [ ] 投篮出手帧自动标记
- [ ] 5 条规则全部能跑出结果
- [ ] 严重等级文案不冒犯（minor/moderate/major）
- [ ] 报告可截图分享（无水印 v1）
- [ ] 历史记录可查看/删除

### 验收清单（性能）

| 指标 | 目标 | 备注 |
|------|------|------|
| 桌面 10s 分析 | < 30s | Spike 实测后调整 |
| 桌面 30s 分析 | < 90s | |
| 移动端 10s 分析 | < 60s | |
| 模型首次加载 | < 5s（桌面）/ < 10s（移动）| |

### 验收清单（用户）

- [ ] 5 名真实业余球员上传过视频
- [ ] 至少 3 名反馈"诊断看起来有道理"
- [ ] 至少 1 名反馈"发现了以前没意识到的问题"
- [ ] 0 名反馈"诊断完全错误"

## 4. Stage 2 · 影子对比 v1.1（2 周）

> Stage 1 用户验证通过后再启动。

### 目标

让用户能把自己的投篮和"标准动作影子"半透明叠加对比，并看到关键关节角度差。

### 任务

| 任务 | 验收 |
|------|------|
| 5 个影子模板数据采集与提取 | 5 个 JSON 文件，每个含完整 33 点序列 + 锚点 |
| 法律咨询 + 命名审查 | 命名中性，文案合规 |
| 髋中点平移 + 躯干长度归一化 | 不同身高用户与同一模板可叠加无错位 |
| 球离手帧锚点对齐 | 用户/模板 release 帧自动对齐 |
| DTW 局部时间扭曲 | set→follow-through 区间内 |
| 影子叠加 Canvas 渲染 | 半透明虚线 + 用户实色 |
| 关键关节角度差曲线 | 肘/肩/膝/腕 4 条折线 |
| 报告整合 | 5 条规则诊断 + 影子差异综合呈现 |

## 5. Stage 3 · 增强（不在本里程碑承诺）

候选项（按优先级粗排，根据用户反馈再定）：
- 训练建议（基于诊断结果输出 1-2 个针对性练习）
- 进步追踪（多次记录的角度趋势）
- 双视角拍摄支持（正面 + 侧面合成更准的角度）
- 移动端原生包壳（Capacitor 或微信小程序内嵌 H5）
- 社区点评（用户互相看视频，复刻"虎扑求大佬"场景）
- 付费方案（先免费验证）

## 7. 风险登记

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| Spike 不过关 | 中 | 高 | 提前做 Decision Tree（服务端 / App / 砍范围）|
| 出手帧 BlazePose 丢点 | 中 | 高 | 升 Heavy 模型；提示用户 60fps 录制；插值 |
| 用户拍摄不规范 | 高 | 高 | 强引导 + 自动视角检测 + 友好提示 |
| 单视角 2D 角度误差 | 高 | 中 | 阈值用区间；v2 加双视角 |
| 影子模板版权风险 | 中 | 高 | 中性命名 + 自录优先 + 法律咨询 |
| 个人开发者动力波动 | 中 | 中 | 每个 Stage 独立可交付；任一 Stage 完成都已有产出 |
| 5 名真实用户招募难 | 中 | 中 | 从虎扑/B 站/小红书自媒体评论区导流（已知存在该需求）|

## 9. 灰度测试招募来源（基于调研）

来自需求调研的真实用户聚集地，可以作为 Stage 1 灰度招募/反馈收集渠道：

- **虎扑实战篮球区**："求大佬看看姿势"类帖发布者
- **知乎**：投篮姿势相关问题的回答者/提问者
- **B 站**：伍大侠、小克篮球、阿龙纳斯等评论区
- **抖音**：科技射手、一田一练等评论区
- **小红书**：#投篮姿势 #女生练投篮 标签
- **个人朋友圈**：身边球友（最容易触达，先用这个）
