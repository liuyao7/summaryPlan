> 版本：v2.0（基于公开调研重写）
> 创建日期：2026-06-01
> 更新日期：2026-06-01
> 平台：Web（PC/移动浏览器优先），微信小程序/App 待 Spike 后再定

---

## 0. 修订说明

v2.0 相对 v1.0 的主要变化：
- 平台从「微信小程序」调整为「Web」，规避小程序对 WebAssembly/MediaPipe 的限制，先快速验证可行性
- 用户场景与画像基于公开互联网调研重写（虎扑、知乎、抖音、B 站、小红书、App Store 评论），不再凭空假设
- 球星方案从「视频对比」调整为「骨骼影子叠加」，规避肖像权与视频版权风险
- 规则引擎以可追溯的论文/教练标准为依据，给出明确角度阈值
- MVP 范围大幅压缩：先做"上传→自己骨骼可视化+1 条规则"，验证有人觉得有用再扩

## 1. 产品概述

### 1.1 真实痛点（来自公开调研）

业余球员对投篮姿势的诉求高度集中在 **「投不进，但不知道哪里错」**。来自调研的具体证据：

- **虎扑实战篮球区**：高频帖子《兄弟们，看看我的投篮姿势有什么问题》《求大佬鉴定》等，回复中反复出现「曲髋」「沉球」「上下肢脱节」「出手前推」等诊断词
- **知乎篮球话题**：《投篮手肘外翻怎么办？》《投篮脱节怎么克制提早举球》—— 用户已建立"自诊断词库"但分不清自己的问题
- **抖音/B 站教学视频评论**：海量"博主帮我看一下"「这是我的视频链接，蹲一个点评」
- **HomeCourt 国区评论**：中国用户最大的吐槽是「国区不可用」「没有中文」「订阅费贵」

**结论**：国内市场存在明确的真空。HomeCourt 在中文区有大量"想用但用不到"，国产同类（篮迹、投篮大师）尚未形成口碑级产品。

### 1.2 产品定位

一个**让业余球员"远程获得专业级诊断"的 Web 工具**：上传一段投篮视频 → 自动指出 N 条具体问题（用业余球员能听懂的词） → 给出可对照的"标准动作影子"。

不是命中率统计工具，不是热力图工具——已经有人做。我们做**会说人话的诊断**。

### 1.3 目标用户（基于调研画像）

| 画像 | 关键标签 | 核心诉求 | 付费意愿 |
|------|---------|---------|---------|
| A · 大学野球场常客 (22) | 6 年球龄、自学库里、肘外飘 | "告诉我哪一步错了" | 单次买断 ≤ 50 元 |
| B · 互联网打工人 (28) | 12 年、上下肢脱节、虎扑求点评 | 量化下肢蹬地与出手是否同步 | 30 元/月或 198/年 |
| C · 校队替补 (16) | 3 年、出手低、想冲首发 | 游戏化训练、出片 | 自己 0 元，家长付费 ≤ 39/月 |
| D · 小红书女性玩家 (25) | 1.5 年、不敢一人野球场 | 单人无人录制 + 隐私模式 | 30–60 元/月（重视出片）|
| E · 四十岁大叔 (38) | 20 年、起跳变弱、想转单手肩上 | 伤病友好分析 + 同年龄段对比 | 买断单次 ≤ 300 元 |

### 1.4 核心价值

1. **会说人话的诊断**：不是数据看板，是教练式自然语言反馈（"你的肘外飘 28°，建议把肘想象成压在身体前方一条线上"）
2. **不上传不订阅不出墙**：浏览器本地推理，视频不离开用户设备；先免费验证价值
3. **可追溯的标准**：每条诊断背后有教学/学术依据，避免"教练之间互相打架"的口碑风险

### Stage 0 · 技术 Spike（v0，1 周）

| 功能 | 说明 | 验收 |
|------|------|------|
| 视频上传 | 选择本地视频文件 | 支持 mp4/mov，≤ 50MB |

| 模块 | 功能 | 优先级 |
|------|------|--------|
| 上传与拍摄指引 | 文件选择 + 「45°/侧面/正后方」拍摄角度引导图 | P0 |
| 投篮区间切分 | 基于手腕 y 轨迹突变检测出手帧 | P0 |
| 骨骼可视化 | 逐帧覆盖 + 出手帧标记 | P0 |
| 规则引擎 5 条 | 肘外翻、出手过低、膝蓄力不足、前臂未垂直、无 follow-through | P0 |

### Stage 2 · 球星影子对比（v1.1）

| 模块 | 功能 |
|------|------|
| 影子库 | 5 名球员的预提取 33 点骨骼坐标序列（不使用任何视频/头像/姓名形象，仅作为标准动作模板代号 A/B/C 或允许的描述如「快速三分模板」「干拔模板」）|
| 时间轴对齐 | 以"球离手帧"为锚点 + DTW 局部精修 |
| 骨骼归一化 | 髋中点为原点 + 躯干长度做缩放，消除身高差 |
| 影子叠加 | 半透明骨骼叠加在用户视频上 |
| 角度差报告 | 关键关节角度差值的逐帧曲线 |

### Stage 3 · 增强（v2+）

历史记录、训练建议、进步曲线、移动端体验优化、社区点评（让真实用户像虎扑一样互相看视频）

## 3. 球星方案（替代视频对比）

> v1.0 的球星视频方案存在严重肖像权/视频版权问题。v2.0 改为 **「骨骼影子」** 方案。

### 3.1 思路

不使用任何球星视频/头像/姓名作为商业素材。改为：
- 离线一次性从公开训练视频中**提取骨骼关键点序列**（仅是数学坐标，不构成版权素材）
- 在前端以**半透明线条叠加**展示，作为"标准动作模板"
- 模板命名采用**风格化代号**：「快速三分模板」「干拔跳投模板」「标准罚球模板」等，**不绑定任何真实球星身份**

### 3.2 法律风险评估

- 骨骼关键点是从视频中提取的**数据/事实**，不是视频本身。在大多数法域不构成对原视频的复制
- 不使用球星头像、姓名、号码、队标 → 规避肖像权与商标
- 「学习库里出手风格」可作为**用户视角的描述**，但不能作为**官方模板名**

→ 即使如此，正式上线前仍需法律咨询。在此之前用「快速 1 号 / 2 号」等中性命名。

### 3.3 影子对比技术路线

来自调研的可落地方法：
- **时间对齐**：先用"球离手帧"做锚点对齐，再在 set→follow-through 区间内 DTW 精修（Sakoe & Chiba 1978 / Skeleton DTW PMC12693942）
- **骨骼归一化**：以髋中点为原点，用躯干长度做单位缩放；左右手镜像统一（Pagnon 博士论文 markerless 流程）
- **角度域比对**：直接比 16 个关节角而非坐标，天然消除身高差

## 4. 规则引擎（基于公开学术资料）

### 4.1 5 条 MVP 规则

| 编号 | 规则 | 关键点 | 阈值 | 来源 |
|------|------|--------|------|------|
| R1 | 肘部外翻 | 12-14-24 (肩-肘-髋) | 上臂外展 < 15°(正常) / 15-25°(轻度) / 25-35°(中度) / >35°(严重) | Okazaki & Rodacki; ShotMechanics |
| R2 | 出手过低 | 16-0 (腕-鼻) | 腕高 < 头顶高视为过低；理想 ≥ 头顶 +0.15·躯干长 | Wissel; NBA 教学共识 |
| R3 | 膝蓄力不足 | 24-26-28 (髋-膝-踝) | 蓄力相最小膝角 90°-120°(理想) / >140°(基本没蹲) | Bin Chi 2014; Irawan 2022 |
| R4 | 前臂未垂直 | 14-16 (肘-腕) | 前臂与铅垂线夹角 ≤ 10°(正常) / >20°(严重) | Okazaki: 高水平 7.9° vs 低水平 19.8° |
| R5 | 无 follow-through | 14-16-20 (肘-腕-食指尖) | 出手后 300ms 内：肘角 ≥160° + Δ腕角 ≥30° + 持续 ≥200ms | Knudson 1993; Wissel |

### 4.2 一些不写进 v1 的规则

来自调研的额外信号（暂列入 backlog）：上下肢同步（蹬地与举球时间差）、出手角（球轨迹切线 45-55°）、肩线水平度、左右手干扰检测、姿势可复制性（多次投篮关节角的方差）。

### 4.3 反"教练打架"机制

调研发现：**「肘外翻」在专业训练师中本身有分歧**（locke locke、UnrealSaber 都认为微微外翻正常）。处理方式：
- 阈值采用区间分级而不是 0/1 判定
- 严重等级采用"轻/中/重"三档，不轻易给"严重"
- 文案不用绝对话术（「你错了」），用「你的角度偏离了大多数职业选手的均值」

## 5. 用户流程

### 5.1 核心流程（3 步走）

```
[1] 选择视频 ──→ [2] 浏览器内分析 ──→ [3] 看报告 + 影子对比
                  (本地, 不上传)         (诊断 + 标注帧)
```

### 5.2 关键场景拆分

| 场景 | 用户来源 | 核心动作 |
|------|---------|---------|
| "求大佬看看" | 虎扑/知乎/B站评论区导流 | 上传 → 看 5 条诊断 → 复制结果到原帖 |
| "改完再录一次对比" | 训练中循环 | 上传旧视频 → 上传新视频 → 看角度差 |
| "我和XX风格像不像" | 自我探索 | 上传 → 选模板 → 看影子叠加 |

## 6. 数据模型

### 6.1 完全本地（v1）

```typescript
// 一切只在 localStorage / IndexedDB
interface AnalysisRecord {
  id: string;
  videoBlobKey: string;     // IndexedDB blob 引用
  createdAt: number;
  poseSequence: Frame[];    // 33 点 × N 帧
  releaseFrameIdx?: number; // 球离手帧索引
  diagnostics: Diagnostic[];
}

interface Frame {
  t: number;                // 时间戳 秒
  points: Array<{ x: number; y: number; z: number; visibility: number }>;
}

interface Diagnostic {
  ruleId: 'R1' | 'R2' | 'R3' | 'R4' | 'R5';
  severity: 'minor' | 'moderate' | 'major';
  metric: number;           // 实际测量值
  threshold: { minor: number; moderate: number; major: number };
  message: string;          // 自然语言
  evidenceFrames: number[]; // 标注帧
}

interface ShadowTemplate {
  id: string;
  codeName: string;         // "快速三分模板" 等中性命名
  description: string;
  poseSequence: Frame[];
  anchors: { releaseFrameIdx: number; setFrameIdx: number };
}
```

## 7. 非功能需求

### 7.1 性能（Spike 后填实测值）

| 指标 | 期望 | 备注 |
|------|------|------|
| 桌面 Chrome 模型加载 | < 5s | 含 wasm + 模型下载（首次）|
| 10s 视频分析耗时 | < 30s | BlazePose Full GPU |
| 移动 Safari 加载 | < 10s | iOS 15+ |
| 移动 10s 视频分析 | < 60s | 性能下降可接受，但要可用 |

> 这些数字在 Spike 之前都是猜测，Spike 通过后应替换为实测值再写进 PRD。

### 7.2 兼容性

- Chrome 100+ / Safari 15+ / Edge 100+
- iOS Safari 15+ / Android Chrome 100+
- 必须支持：File API、Canvas、WebAssembly、WebGL
- 不支持的浏览器给降级提示

### 7.3 隐私

- **核心承诺**：v1 全部在浏览器内完成，视频/骨骼数据不离开本机
- 仅模型文件从 CDN 下载（首次缓存后离线可用）
- 报告本地存储于 IndexedDB，用户可一键清空
- 无埋点、无登录（v1）

## 8. 风险与挑战

| 风险 | 影响 | 应对 | 备注 |
|------|------|------|------|
| BlazePose 在快速出手帧丢点 | 高 | 提升到 60fps 录制；Heavy 模型；丢点插值 | 出手仅 1-2 帧很关键 |
| 单视角 2D 透视失真导致角度误差 | 高 | 拍摄引导限制角度；规则采用区间而非精确判定；v2 加双视角 | 论文显示 2D 误差 5-15° |
| 球星骨骼数据来源争议 | 中 | 中性命名 + 法律咨询 + 必要时换为"教练示范"自录 | |
| 用户拍摄不规范 | 高 | 强引导拍摄（45°/侧面图示）；自动检测视角并给提示 | 调研里这是入口级痛点 |
| 移动浏览器内存/续航 | 中 | 抽帧降低（如 15fps 起步）；分析中显示进度 | |
| 教练之间标准打架 | 中 | 区间分级 + 文案柔化 + 多风格模板 | |
| 用户期望值过高（"教练级")| 中 | UI 明示「辅助参考，不替代教练」 | |

---

## 9. 不做的事（边界）

- **不做命中率统计 / 热力图**：篮迹、投篮大师在做，重复且不在我们的差异化上
- **不做实时分析**（v1）：先离线分析，避免实时帧率/边缘 case
- **不做账号系统**（v1）：没必要
- **不做付费**（v1）：先验证价值
- **不绑定任何球星真实身份作为商业素材**：规避法律风险
