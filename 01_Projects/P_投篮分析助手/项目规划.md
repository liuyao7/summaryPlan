## 0. 修订说明

v2.0 主要变化：
- 平台从微信小程序调整为 **Web 优先**（PC + 移动浏览器）

- 砍掉所有未验证的优化项（Worker、componentDefines 等小程序特有）

## 2. 技术架构

### 2.1 v0 / v1 技术栈（Web）

| 类别 | 选型 | 说明 |
|------|------|------|
| 平台 | Web SPA | 浏览器内运行，无后端 |
| 构建 | 暂时纯 HTML + ESM | Spike 阶段不引入 Vite/构建链；MVP 视情况引入 Vite + TypeScript |
| 姿态模型 | MediaPipe Tasks Vision (Web) - BlazePose Full | 33 点，含手部，GPU/WebGL 推理 |
| 视频处理 | 浏览器原生 `<video>` + Canvas | 不引入 FFmpeg.wasm（v0 不需要）|
| UI | 原生 HTML/CSS（v0），MVP 视情况引入轻量框架 | 不上 React 之前先用原生 |
| 存储 | IndexedDB | 视频 blob + 分析记录 |
| 部署 | Vercel / GitHub Pages（静态托管）| 零成本 |

### 2.2 不选小程序的原因

- MediaPipe Web 依赖完整 DOM、WebAssembly 高级特性、WebGL → 小程序逻辑层无 DOM，能力受限
- FFmpeg.wasm 在小程序无法直接使用
- 视频处理 API 受限（`wx.createVideoDecoder` 能力有限）
- 个人开发者快速试错，Web 部署成本/迭代速度都更优
- 验证用户价值后再决定是否包壳到小程序/App

### 2.3 系统架构

```
┌────────────────────────────────────────────────┐
│  Browser (用户设备)                             │
├────────────────────────────────────────────────┤
│  UI Layer                                       │
│   上传 │ 引导 │ 视频播放 │ 骨骼覆盖 │ 报告      │
├────────────────────────────────────────────────┤
│  Logic Layer                                    │
│   抽帧 │ 推理 │ 切分 │ 规则引擎 │ 影子对齐      │
├────────────────────────────────────────────────┤
│  Inference Layer                                │
│   MediaPipe Tasks Vision (BlazePose Full)       │
│   WebGL / GPU                                   │
├────────────────────────────────────────────────┤
│  Storage                                        │
│   IndexedDB (视频/记录)  │  CDN (模型/影子模板) │
└────────────────────────────────────────────────┘
```

### 2.4 核心处理管线

```
视频文件
   │
   ▼
[1] 抽帧 (target: 30fps)
   │
   ▼
[2] BlazePose 逐帧检测 → 33 关键点序列
   │
   ▼
[3] 投篮区间切分
   - 锚点: 球离手帧 (手腕 y 急速上升后回落的拐点)
   - 输出: setFrameIdx, releaseFrameIdx, followFrameIdx
   │
   ▼
[4] 规则引擎 (R1-R5)
   - 每条规则取自己的关键帧 → 计算指标 → 阈值分级
   │
   ▼
[5] 影子对齐 (Stage 2)
   - 髋中点平移 + 躯干长度归一化
   - 球离手帧锚点对齐 + DTW 局部精修
   │
   ▼
[6] 报告生成
   - 自然语言诊断 + 标注帧 + 影子叠加可视化
```

## 4. 关键技术决策

### 4.1 为什么选 BlazePose Full

| 候选 | 选用 | 理由 |
|------|------|------|
| BlazePose Lite | ✗ | 精度不够，投篮峰值帧易丢点 |
| **BlazePose Full** | **✓** | 33 点含手部，移动端友好，文献中精度达标 |
| BlazePose Heavy | 备选 | 桌面端性能允许时启用 |
| OpenPose | ✗ | Web 部署复杂 |
| MoveNet | 备选 | FPS 高但 17 点不含手指 |

来源：Frontiers Physiology 2025 综述、Pau et al. 2021、J Mod Educ Res 2024（BlazePose Full > OpenPose 在篮球数据集上）

### 4.2 抽帧策略

| 阶段 | 帧率 | 备注 |
|------|------|------|
| 默认 | 30 fps | 大多数手机录制默认 |
| 出手附近 ±0.5s | 60 fps（如视频源支持） | 出手仅 1-2 帧，需要密集采样 |
| 移动端降级 | 15 fps | 性能受限设备 |

实现方式：先用 `requestVideoFrameCallback`（Chromium）；Safari 退回 `currentTime + onseeked`。

### 4.3 投篮区间切分

不引入复杂模型，先用启发式：
- 检测手腕 y 坐标快速上升（蓄力→出手）后突变（球离手）的帧 = `releaseFrameIdx`
- 向前回溯到膝角最小帧 = `setFrameIdx`
- 向后取 300ms = `followEndIdx`

→ MVP 验收要求：在调研团队 20 段标注视频上 ≥ 70% 准确切分。不达标再考虑用 SpaceJam 数据集训小模型。

### 4.4 影子对比方案（Stage 2）

```
[影子模板数据准备] (一次性, 离线)
  公开训练视频 → BlazePose 提取 → 人工筛选高质量片段
  → 归一化坐标 + 标注锚点帧 → 存为 JSON
  → 文件名/描述全部使用中性命名 (如 "quick-3pt.json")

[运行时对比]
  用户骨骼序列 + 模板序列
  → 各自以 mid-hip 为原点平移
  → 各自用躯干长度归一化
  → 锚点对齐: 用户 release 帧 ↔ 模板 release 帧
  → DTW 在 [set, follow-through] 区间内做局部时间扭曲
  → 半透明 Canvas 叠加 (用户实色 + 模板半透明虚线)
  → 各关节角度差曲线
```

### 4.5 不引入的东西（v0/v1）

- **后端 / 数据库**：视频不上传，没必要
- **账号 / 登录**：MVP 阶段不需要
- **复杂构建链**：v0 纯 HTML，v1 视情况上 Vite
- **状态管理库**（Redux/MobX）：单页应用 + 简单状态，不需要
- **UI 框架**：先 vanilla 后再说

## 5. 数据来源与版权策略

| 资源 | 用途 | 来源 | 风险 |
|------|------|------|------|
| MediaPipe 模型 | 推理 | Google CDN，Apache 2.0 | 无 |
| 影子模板（5 个） | 标准动作对比 | 自录 + 公开视频提取骨骼坐标 | 中 - 见下 |

**影子模板版权策略**：
- 不存储/分发任何视频/头像/姓名作为产品素材
- 仅存储 33 点 × N 帧的数值坐标
- 命名采用风格化中性代号（quick-3pt / pull-up / standard-ft 等）
- 用户视角的描述（"快速三分模板，参考库里风格"）可在引导文案出现，但不在产品默认 UI 暴露
- v1 上线前必须完成法律咨询

## 7. Spike 验收清单（Stage 0 必过）

只有以下全部通过才进入 Stage 1：

- [ ] 桌面 Chrome 模型加载 < 5s
- [ ] 桌面 10s 视频分析 < 30s（端到端，含模型推理）
- [ ] 桌面 30s 视频分析 < 90s
- [ ] iOS Safari 跑通（性能可下降，但不崩）
- [ ] Android Chrome 跑通
- [ ] BlazePose 在出手前后 5 帧不出现明显丢点
- [ ] 规则 R1 在 5 段对照视频上能正确分级（标准 vs 外翻）
- [ ] 规则 R1 的角度数值在多次运行同一视频时方差 < 2°（稳定性）

任何一项不过：
- 性能不达标 → 评估服务端推理（Node + onnxruntime + GPU）
- 移动端不通 → 评估只做 PC Web，或包壳为原生 App
- 关键点不稳 → 换 BlazePose Heavy 或加双视角

## 9. 风险登记

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| BlazePose 出手帧丢点严重 | 中 | 高 | Heavy 模型；插值；提示用户提高录制帧率 |
| 单视角 2D 误差大 | 高 | 中 | 强引导 45°/侧面拍摄；阈值用区间分级 |
| 移动端性能不可用 | 中 | 中 | PC 优先；移动端降级帧率 |
| 用户拍摄不规范 | 高 | 高 | 引导图 + 视频范例 + 自动检测视角 |
| 影子模板法律风险 | 中 | 高 | 中性命名 + 自录优先 + 法律咨询 |
| 个人开发者精力有限 | 高 | 中 | 严格按 Stage 推进；Stage 0 不过就停 |
